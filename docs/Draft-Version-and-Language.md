# 草稿版本、錯誤提示與繁體中文

2026-09-10，依使用者確認範圍實作。

## 草稿版本

- 開啟 Draft、送出 Draft 前查詢最新「已發布」版本；尚未發布的活動編輯不影響申請。
- 有新版時顯示目前／最新版本，確認後才套用。暫不更新可繼續編輯；再次送出仍會提示，不可繞過後端檢查。
- 套用前儲存目前輸入，保留個資、銀行資料與附件。重算產品估算、更新幣別、清除條款／隱私同意並回到確認步驟；行銷選擇保留。不再適用的產品不自動刪除，送出時重新驗證。
- 套用後不自動送出，使用者須檢查並重新勾選同意。提示期間又發布新版，後端拒絕舊目標版本並要求重新確認。
- Submitted、UnderReview、MoreInfoRequired 與後续階段固定原版本，補件不重新套用活動新版。
- API：GET `/api/operations/claims/{id}/version-check`；POST `/api/operations/claims/{id}/apply-version`，傳入 `expectedLatestVersionId`。使用 ABP Application Service、Owner 權限、交易與樂觀並行控制，紀錄新舊版本稽核。

## 前台體驗

- 表單錯誤置於底部操作區，role=alert 並自動聚焦／捲動；連續相同錯誤也重新提示。更新失敗顯示於版本對話框內。
- 頁首 English／繁體中文切換，localStorage 記住介面偏好，同步 HTML lang。
- 介面偏好與案件 Language 欄位分開；案件可選 `zh-TW`，不會因切換介面改動案件內容。
- 翻譯範圍為前台活動瀏覽、申請、案件追蹤與銀行更改。後台維持既有語言。動態活動名稱、產品、通路、條款與隱私文本仍顯示後台原文，不自動翻譯。

## 驗證

後端 29 項測試、HTTP 整合 24 項通過，涵蓋過期草稿送出阻擋、明確套用、資料／附件保留、同意重設、目標版本過期與補件固定版本。本次沒有 schema 異動，無需新增 migration。

前後台 TypeScript 檢查及 public-web Docker 建置通過。瀏覽器合成案件驗證開啟提示 v1→v2、暫不更新後再次送出仍提示、確認後姓名／發票／銀行資料保留、回饋 €50→€60、必要同意清除；缺附件送出時中文錯誤自動聚焦且與按鈕同屏可見。繁體中文偏好重新整理後保留，未修改既有使用者案件。

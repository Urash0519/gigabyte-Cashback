# 使用者樣式版本 UI/UX 修正與驗證 — 2026-10-08

本次只調整 `/reference/`、`/admin/reference/`，前台仍以使用者提供的 26Q1 Landing Page Screenshots 黑金活動樣式為主，後台保留既有參考報表風格。原 `/`、`/admin/` 和共用業務元件沒有修改；兩種呈現繼續使用相同 API 與資料。

開始修正前已閱讀 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)，並檢查專案 CSS Variables、共用 UI、ClaimForm 和參考版樣式。以下是本次實際檢查結果，並非完整 WCAG 合規認證。

## 問題與修正前後

| 嚴重程度 | 發現的問題 | 修正後 |
| --- | --- | --- |
| P1 | 黑色前台繼承淺色共用元件的深灰標籤，閱讀困難；白字橘色 CTA 和部分青綠色後台控制項對比不足 | 僅在參考版調整標籤、按鈕文字／底色和輔助文字；保留黑金與青綠主色 |
| P1 | 375px 案件詳情整頁溢出至 404px；檔案上傳欄位巢狀 grid 不易閱讀 | 加入子區塊 `min-width:0`、長文字換行及上傳區塊直向排版 |
| P1 | 後台 761–999px 漢堡選單與側欄斷點不一致 | 統一 999px 以下的開合行為；支援 Escape 關閉並將焦點還給選單按鈕 |
| P1 | 手機導覽與彙總標題的 flex basis 造成不合理的大面積留白 | 手機模式重設 flex basis，主要操作直接出現在內容旁 |
| P1 | 欄位顯示選單及活動版本對話框可能超出可視範圍 | 限制視窗高度、提供內部捲動；開啟欄位選單時將觸發點帶至可視位置 |
| P1 | 表格較寬或資料較多時，缺乏可理解的捲動策略 | 表格容器具名稱與鍵盤焦點；保留表格水平捲動，營運長表限定高度並固定表頭 |
| P1 | 輸入中的申請資料在切頁、返回或登出時容易遺失 | 新增離開前提示與 beforeunload 保護，涵蓋欄位輸入及商品新增／移除；取消離開會保留輸入，儲存成功解除保護 |
| P1 | 報表 API 錯誤容易被呈現為空資料，篩選日期錯誤缺少明確訊息 | 分離 Loading／Error／Empty 狀態、增加 Retry；日期錯誤提示並聚焦欄位 |
| P2 | 部分「完整報表」按鈕目的地不符合卡片內容 | 交易卡開啟付款報表，商店／產品／國家卡開啟對應彙總 |
| P2 | 手機文字偏小、控制項範圍不足，產品分類選中狀態不明顯 | 調整字級與點擊範圍、手機輸入框 16px，補上分類選中標示與一致焦點 |
| P2 | 追蹤搜尋接受全空白字串，登入後不易延續查詢 | 修剪輸入、具體錯誤訊息與焦點；登入後保留查詢 |
| P2 | 活動卡圖片加入固有尺寸後被拉成過高的卡片 | 保留圖片尺寸資訊，卡片使用自動高度與固定比例 |
| P2 | 詳細報表可以隱藏全部欄位 | 保留最後一個可見欄位，控制項有清楚的 Disabled 狀態 |
| P2 | 缺少跳至內容連結、路由焦點與部分表格語意 | 增加 Skip link、頁面標題、欄位 scope／caption、可見焦點與 reduced motion |

本次未發現可確認的 P0 資料錯誤。申請、審核、付款、取消及條款版本更新的業務規則沿用既有實作。

### 流程測試

### 2026-10-08 導覽捲動補修
